# 人岗匹配：证据评分 v1

先保存岗位及经 HR 确认的候选人，再从侧栏进入“人岗匹配”。选择双方，核对各维度指标，点击计算。
不修改岗位、候选人或招聘状态，不自动淘汰，不保存新的匹配记录，也不调用外部 API。

## 评分

- 维度和满分严格取自岗位 `competency_model`，权重必须合计 100，最多两位小数。
- 默认指标优先从维度描述提取；通用维度采用界面中公开的规则建议，HR 可修改。未知维度不猜测指标。
- 同维度各指标等分权重：实践证据或学历达标=1；技能栏自述=0.5；无证据=0。只取每项最强证据，重复记录不增加分数。
- `score = max_score × 各指标达成系数的平均值`，四舍五入到两位小数。`total_score` 只由各维度已显示分数求和。
- `confidence` 为指标证据可信度均值：实践/学历=0.8，自述=0.5，无证据=0；不是录用概率，也不再乘入分数。
- 返回原文片段和 `skills[0]` 等定位；无证据输出“暂无明确证据”。不把职位名称作为技能，不从岗位名称推断候选人能力。

## 建议规则

证据覆盖率是有证据指标所占的岗位权重。覆盖不足 60% 时优先为“信息不足”；否则总分低于 60 为“匹配度较低”，其余为“建议进一步评估”。仅有上述三种建议。
这套阈值和系数是可解释的工程规则，不是经过统计验证的招聘标准，不得用于自动拒绝候选人。
低分仅表示当前简历的证据覆盖不足，不证明实际能力较低。

## 边界

- 只读取已确认简历的职业字段，忽略姓名及额外个人属性。含显式敏感内容的记录不作为证据；敏感岗位指标会被拒绝。
- 不用年龄、性别、婚育信息。学历只从教育记录判断，不计算年龄，不根据毕业时间推测年龄，不评价院校声望。
- 本地规则采用有限同义词、动作词、否定词和职位词过滤，不理解任意语义或所有否定。涉及职位词的整段会保守忽略，可能漏掉有效证据。
- 学历识别只覆盖中文专科/本科/硕士/博士，复杂替代条件与专业要求需人工单独核实。在读及肄业不视为已达学历要求。
- 通用项目维度默认指标为“项目交付”，仅列项目名称不能证明交付。复杂岗位应由 HR 明确口径。
- Mock 岗位在页面明确警示，仅用于演示。所有证据仍需核验真实性，系统不作录用决定。

## 验证

运行 `.\.venv\Scripts\python.exe -m pytest -q`。
测试覆盖总分求和、权重、逐项简历证据定位、职位名称不计分、缺失证据、敏感信息排除、只读查询和页面选择。
