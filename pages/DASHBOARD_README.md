# Recruitment Dashboard

Dashboard 使用 Plotly 展示四项指标和四张图。所有统计只来自 SQLite 中已保存数据，不生成虚构样本。

## 口径

- 候选人数：`candidates` 表中的确认简历数；岗位数量：`jd_jobs` 中岗位数。
- 平均匹配分：所有当前人岗组合最新报告的算术平均。重复计算同一组合会覆盖统计快照，避免重复计数。
- 高匹配候选人数：每位候选人所有最新报告的最高分达到 80 分，按候选人去重。80 是可见的产品阈值，不代表录用概率或自动决策。
- 分布图按人岗组合统计；岗位图按岗位汇总最新报告；能力图先计算每个维度 `score/max_score×100`，再按同名维度平均。
- 已删除或找不到当前岗位/候选人的孤立报告被排除并显示警告。

## 漏斗

“收到简历”统计已确认保存的候选人；“AI辅助筛选”统计拥有匹配报告的候选人。
“HR人工确认、进入面试、Offer”只来自 Dashboard 的人工阶段记录，并按达到该阶段及之后阶段累计。
同一候选人有多个岗位时，各阶段按候选人去重；因此漏斗衡量人数，不是申请人岗组合数。
记录 Offer 只表示现实流程中已经发生，不会生成、发送或接受 Offer，也不会淘汰候选人。
修正阶段可重新保存另一个实际阶段；系统保留当前值，暂不保留完整历史审计日志。

## 数据与限制

匹配页面计算成功时会重算校验并保存报告快照；任意手写总分不能入库。
旧版本在本功能上线前计算过但未持久化的报告不会回填，需要重新计算。
报表不使用年龄、性别、婚育或照片。页面含候选人姓名，属于本地 HR 工作台数据；请限制数据库和服务访问权限。
样本量很小时均值和高匹配数容易误导，页面同时显示报告数；所有图表仅用于流程观察，不用于自动录用决策。

运行 `.\.venv\Scripts\python.exe -m pytest -q` 验证计算、去重、阶段统计、报告校验和页面图表。
# 展示口径更新

首页仅显示保存记录与最新人岗报告数量，不展示跨岗位均分或候选人最高分。
分析页默认选择一个岗位，再按模型权重、评分指标与规则版本分组；显示当前组样本量 n。
均分和 ≥80 报告数仅描述该组最新快照，不是能力排名或招聘有效性指标。
不同模型不可直接比较。旧报告缺少的模型描述按独立口径处理。

「已确认保存候选人（全库）」不是投递人数；「已生成匹配报告」不是已筛选或通过人数。
全库人数与岗位样本分母不同，因此记录数量使用条形图，不展示转化百分比。
人工阶段按已记录阶段累计计数，不推断未记录的实际流程。
